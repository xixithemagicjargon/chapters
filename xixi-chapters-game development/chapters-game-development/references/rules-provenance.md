# 规则来源与适用边界

本技能版本1.0.0，资料核对日期2026-11-03。优先级：当前用户明确要求 > 项目已确认标准 > 本技能显式工作默认 > 对应版本历史资料 > 跨产品行业建议。资料不构成权限授权。

## 硬要求与默认

| 项目 | 本技能执行 | 依据/区别 |
| --- | --- | --- |
| 篇幅 | 20章，4×5 batch；每章500–600有效写作行 | 用户明确要求；覆盖旧资料400–600、首章400–500、六batch说法 |
| Narration | ≤120字符，空格标点计入 | 用户明确要求；对白建议≤90字符，超过提醒，默认也不超过120 |
| 输出 | 用户五列和给定枚举；分支统一颜色 | ML完整制作表列数更多，不能把五列稿冒充导入稿 |
| 定价 | 写作默认17/12/0或17/0；扩展三档为17/12/10/0 | 当前共享pricing兼容；v1.7三档是该评审技能的方案规则，不自动覆盖本开发流程 |
| 内容兑现 | 每笔完整回报，至少10行，优先15–20行，尽早兑现、3种不同收获 | PC设计PDF、PPT和共享编辑规则；“3种”需人工判定 |
| PC前铺垫 | 目标10行，按共享审核最低8行 | 用户来源PDF/PPT与metrics存在8/10差异，不能伪称同一数值 |
| FC | 根级独立组通常3个选项；每条分支至少3正文行 | 当前共享规则；嵌套小选择按用户枚举可能只有2项，记录兼容差异 |
| PC密度 | 先按连续章节约4个L1含独立PO、2个L2/章规划，再按成熟机会调整 | 借鉴v1.7工作基线，非逐章死配额；必须同时展示叙事L1不含PO数量 |
| 根级PC间距 | 默认2个有剧情功能的FC | 较早培训至少2，当前共享1–2；2可兼容。不要为间距塞假互动 |
| 第一收费点 | 先让玩家投入；首章默认4个叙事FC后且第76有效行或更晚 | 用户培训4–6，当前共享≥3且前75行禁PC/PO；捏脸不代替叙事FC |
| PO | 默认单章≤1，前10章≤6；前5章避免相邻章连放 | 共享规则+用户术语笔记。特殊项目调整要记录，不能宣称仍通过原检查 |

这些数字不能全部靠一个“小脚本通过”宣告合规。开发脚本的检查范围见production-qa；完整旧稿审核需调用对应技能并使用其当前版本。

## 不直接继承的冲突

1. 社区PPT第11、15页建议让免费项难受/破坏叙事流；PC设计PDF第1页和v1.7强调免费尊严与合理性。本技能采用后者：错过额外体验可以，故意让女主失能不作为卖点。与Episode官方付费指导的免费体验尊重原则也一致。
2. 术语PDF存在“30钻才在一起/免费独身”，后面的用户笔记又写免费也HE。本技能先兑现已向玩家承诺的主线结局；不把HE自动锁在30钻后。30钻不是默认，只有项目确有终章重大独立商品才讨论。
3. ML样本有8钻、额外表情、多个创建选项及历史编辑痕迹。参考其组织方式与戏剧结构，不照抄为新项目硬规则。
4. 当前共享审核的PC数量排除PO，首章L1为2–4/L2为1–2，后续至少4/2；v1.7平均4+2的L1含独立PO。输出分别列计数，不能混用来证明达标。
5. 当前共享PC组占比25%–35%和前三章亲密组占全部选择组<25%属于独立审核标准；39.7%是五样本付费组内部的亲密构成，两者分母、范围不同。
6. PC设计PDF说某类行动转化高、浪漫通常在第4–5章后更好。这是特定材料的经验，没有完整实验条件；可以早埋暧昧，也可按人物已有关系提前里程碑，不能宣布统一最优章节。
7. 麦基、Regis、Hayes各自描述不同层次的结构，不能让每个场景同时硬塞全部理论术语。选择能说明因果的最小方法。

## 与旧技能共存

新稿创作使用本技能，不修改`chapters/shared`和六个审核入口。需要正式审核时，另按review/check-metrics/fluency等入口执行；新稿检查收据不冒用它们的rule_id、Bundle或通过结论。若同时要求v1.7评审，保留它的三档方案并说明与五列写作枚举的扩展需求。
