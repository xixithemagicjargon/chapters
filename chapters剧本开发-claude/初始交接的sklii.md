# Chapters 新人编辑入职知识库

本 Skill 包含 Chapters 互动小说平台编辑工作所需的全部核心知识，用于快速、准确地回答新人编辑的各类工作问题。

## 一、Chapters 产品基础

### 团队构成
- **深圳团队**：国内编辑，以 UGC 改编为主，辅以 PGC 和 PCCP
- **美国 SND 团队**：资深编辑，有 A 级以上爆款书经验，以 PGC 为主
- **美国 ND 团队**：初级编辑，以 Reelshorts 改编为主

### 书籍类型对比

| 模式 | 核心流程 | 编辑职责 | 目标钻耗 | 适用编辑 | 周期 |
|------|---------|---------|---------|---------|------|
| **PGC** | 编辑写20章大纲（含PC），联系海外写手创作剧本，审稿、配置、上线 | 全流程主导 | 300w+ | 成熟编辑 | 3个月 |
| **UGC** | 选取已有数据验证的UGC作品，调整节奏并添加PC | 选书、改编、独立完成剧本 | 150w+ | 新编辑 | 2-3个月 |
| **PCCP** | 联系外部作者在UGC编辑器上创作，编辑负责指导与审核 | 类似责编，不直接创作 | 待定 | 无明确限制 | 待定 |

> ⚠️ **新编辑第一本书做 UGC 改编。**

## 二、周更书籍机制

### 更新节奏
- 一般书籍 **20章**，分为 **6个batch**
- 节奏：**5/3/3/3/3/3**（第一个batch 5章，之后每个batch 3章）
- 超过25章可考虑7个batch，但完结成绩统计的是 **上线后49天** 的数据，batch数量不影响成绩

### VIP 提前看
- VIP 玩家比普通玩家多看一个 batch
- 首周更新 batch1+2，之后每周新更一个 batch

### 上线前准备
- 上线前需完成 **3-4个 batch**（不强制全部完成）
- 更新节奏在开书时确定好，有变动要提前通知其他部门

## 三、稿子结构规范（⚠️ 新人最易出错）

### 整体结构
- 全篇 **20章**（不少于20章），每章 **400-600行**
- 每章 **4个一级PC + 2个Sub-PC**
- 每两个PC之间 **至少2个FC**

### 第一章特殊要求
- 行数：**400-500行**为佳
- PC数：**3-4个PC + 1-2个Sub**
- 第一个PC **之前**必须有 **4-6个FC** 铺垫剧情

### 从第三个Batch开始
- 可根据情节适当增加PC数量（如从4个增到5-6个）

### 最后一章（第20章）
- PC数量可增加到 **7-8个**，配合结局高潮剧情

## 四、PC / PO 配置规范（⚠️ 新人最易出错）

### PC（Premium Choice）配置

| 选项数 | 付费选项 | 免费选项 | 价格模板 | 适用场景 |
|-------|---------|---------|---------|---------|
| 3个 | 2个 | 1个 | 17/12/0 钻 | 日常剧情分支 |
| 4个 | 3个 | 1个 | 17/12/8/0 或 17/12/10/0 | 剧情复杂分支 |
| 2个（尾声） | 1个 | 1个 | **30钻**/0 | 最终决策（如是否与男主在一起） |

### PO（Premium Outfit）配置
- 一般 **4个选项，3个付费，1个免费**
- 价格：**17/12/10/0 钻**
- 频率：一般 **2章1个**PO
- ⚠️ PO付费率很高，衣服选择非常重要

### PO 衣服选择原则
玩家喜欢**性感、露肤度高**的衣服，各价位参考：

| 价格 | 风格 |
|------|------|
| **17钻** | 最华丽，抹胸/吊带为主，配有首饰，与其他选项要拉开明显差距 |
| **12钻** | 稍次于17钻，华丽程度略低 |
| **10钻** | 露肤度进一步降低，如短裙 |
| **0钻（免费）** | 最普通，如白T+裤子、长裤等 |

- ⚠️ 玩家**特别不喜欢背带裤**，可以用作免费选项
- 17钻的衣服一定要跟其他选项拉开差距，突出高价值感

### 付费逻辑
- 免费选项需保留剧情合理性
- 付费选项提供额外细节或高光片段
- **每个PC内容至少要大于10行**
- 最终章关键决策用高价（30钻）强化情感价值

### 一级PC vs 二级PC（Sub-PC）
- **一级PC**：所有玩家都能看到的付费选项组
- **二级PC（Sub-PC）**：只有选了一级PC内容的玩家才能看到的付费选项组

## 五、稿子格式填写规范（⚠️ 新人最易出错）

**稿子模板：** https://docs.google.com/spreadsheets/d/1lL3-wSFQFR-z33E-Cj-9NQxnp9ZkOcW04i73RjR7ApY/edit?gid=2000637938#gid=2000637938
- 打开后看 **【template】tab**，里面有打电话、callback、PO 等各种情况的格式示例

稿子模板列说明：**Dialogue Type、Line、Text Type、Character、Script、Emotions、Backgrounds、Thought Bubble、Clothing、BGM、Panning、备注**

作者负责填写：Dialogue Type、Text Type、Character、Script、Emotions、Background、Thought Bubble
编辑负责填写：Clothing、BGM、Panning、备注

### Dialogue Type（层级）
- 层级不要乱，否则导入会报错
- 常用类型：Text、Choice 1/2/3、Premium Choice 1/2/3、Sub Choice、Narration_PopUp、Narration_Prompt

### Line 列（选项标记 & 钻石赠送）
- 写选项的 a/b/c 以及钻石赠送
- **第一章可赠送3个钻石，之后每章1个**，只加在 FC 上
- 格式：FC选项写 `a+1 gem`；PC写 `a - 17 gems`

### Text Type（特殊类型）
- 视频电话：`Video chat`（⚠️ 注意要标明电话那边的人穿什么衣服、背景在哪里）
- 电话：`Phone`
- 短信：`Text`
- 不同选项后有不同反馈：`Call back`

### Character（角色名）
- 所有角色用自己名字，MC 先拟定一个默认名字（玩家命名时显示在对话框里）
- 如果人物有两个名字，括号写别名：如 `Vincenzo(???)`
- Narration_PopUp：出现在选项前的话 Dialogue type 是 `text`，出现在选项里就跟随选项
- Narration_Prompt：橙色高亮旁白框，用于提示特别重要的事情

### Script（脚本内容）
- **全文不要中文标点符号**
- 文本中的表情 emoji 需从 emoji 库复制

### Emotions（表情）
- **每个对白都要有表情**，特别是新增对白要检查
- 常用：`neutral`、`smile`、`shy`
- ⚠️ 慎用：`confused`、`laughing`、`pleasure`（显示效果不好）

### Backgrounds（背景）
- 填写 Dropbox 里找到的场景资源文件名
- **一般章节第一个场景会 pan**（开启 Panning）
- ⚠️ 不要用 `old background` 文件夹里的图，新图质量更好

### Clothing（服装）—— ⚠️ 最容易漏填
需要填写的情况：
1. **每个人物出现第一次**
2. **每次换装**
3. **每章第一次出现**（即使没换衣服也要把上章穿的写上去）
4. PO 衣服名字后写资源名字
5. **PO选择后MC第一次说话**，备注写：`MC player choice in chapter x`
6. 一章有多次换装，下一章MC的衣服写：`mc first player choice in chapter x`，`mc second player choice in chapter x`
7. 男女主开头选择默认服装要写
8. 男女主做爱可写：`no top`、`no bottom`、`MC nude`等
9. 衣服湿了写：`衣服名 + wet`
10. **衣服需要调整但还未命名**：Clothing 填写 `原资源名 + adjust`，备注写：`这里衣服需要调整，详情看美需`

### BGM（背景音乐）
- 一般跟随场景/情节更换，**每章5-10个**
- ⚠️ 注意有些BGM有中文台词，不要用

### 备注（Notes）
- 多个物品选项在备注写：`Multiple Object Choice`
- 所有物件的资源名写在备注
- 人物受伤加 dec，开始和结束都要写，结束写：`remove + 资源名`
- 流血写：`衣服 + 血`
- 特殊情况：人物在选项里换了衣服，选项后第一次说话在备注里写衣服跟选项变化

### 其他注意事项
- **稿子里不要有超链接**
- **资源名不要后缀**（不要写 .jpg、.mp3 等）
- 稿子写完后放在文件夹里按照 batch 打包

## 六、美需（Art Request）规范（⚠️ 新人最易出错）

### 上线流程时间节点
- **上线前1.5个月**：提交美需 + 封面需求（Cover Request）
- **上线前1周**：Promo Text（Keyword/Title/Blurb/Push/人物卡/Blurb BGM/MC-LI intro）
- **第一个batch提前3周**，之后提前2周提交稿子
- **上线前3-5天**：QA

### Art Request 内容

**好看的脸/发型参考文档（25年11月-26年2月数据）：**
- 这两份文档记录了近期各书玩家选取率高的脸和发型资源名，选脸时可参考
- **女脸参考**：https://alidocs.dingtalk.com/i/nodes/N7dx2rn0JbZQAvopUyGgEOgpJMGjLRb3
- **男脸参考**：https://alidocs.dingtalk.com/i/nodes/QG53mjyd80RNK6Okhv6eNq1XV6zbX04v
- 常见高人气女脸资源名举例：`HO_FM_MC__Becca01`、`MFH_MC_Megan_White`、`Pilot_FM_White_02`、`DED_MC_Gwen Bennet_White`、`TTA_MC_Kara_White`、`RMD_MC_white_Ellie`
- 常见高人气男脸资源名举例：`CTHC_M_LI_Satgelion07`、`M_00460_White_FAH_Bear`、`Pilot_M_White_01_beard`、`AAS_LI_Dom_White_Beard`、`ADMB_M_LI_Chase05_beard`

**MC/LI（男女主）：**
- 女主：脸 8张 + 发型 8张（可额外2个付费的），男主：脸 12张 + 发型 12张
- **4个人种要平均**，发型也要注意挑选适合黑人的发型
- 男女主默认衣服一般各 6件
- 男女主在书内需要用到的衣服 + PO的衣服
- ⚠️ **脸部顺序：把每个肤色组中最好看的放第一位**，搭配相应发型和默认服装

**其他角色（Other Characters）：**
- 配角的脸 + 发型 + 衣服
- ⚠️ 注意亲戚的 race match（种族搭配）
- 不重要的角色可参考 Dropbox：`reuse characters - fully referenced`（有搭配好的脸+发型+衣服，衣服可换）
- ⚠️ 配角发型和衣服不要跟MC/LI 撞，也不要跟其他配角撞

**Objects（物品）：**
- 用 Dropbox 链接搜关键词查找
- ⚠️ 物品最好不要涉及MC/LI 的脸（制作难度高，如需照片可模糊脸部）

**Backgrounds（场景图）：**

### ⚠️ 背景命名规则（最容易出错）
新增/调整的背景**必须命名**，规则：

```
书名缩写_地方描述_室内(i)/室外(o)_白天(d)/夜晚(n)/黄昏(ss)
```

示例：`mka_firstclass_i_n`（MKA书，头等舱，室内，夜晚）

- ⚠️ 夏天的书注意背景里的雪、壁炉的火等季节性细节
- 背景一般开场会 Pan，最后定位在手机页面大小的尺寸，可以指定定位到背景的左/右/中（默认中间）
- ⚠️ 不要试用带格子的老旧背景图

**新服装命名规则：**
```
女主名字 + 书名 + p1
```
示例：服装命名 `Gwyneth EOD p1`

**封面（Cover Request）：**
- 按模板填写，美术先画黑白线稿确认构图，再填色
- ⚠️ 封面的脸需要跟美需里的脸对应（玩家在游戏中可选到封面的脸）
- ⚠️ 调整终版时注意观察同期上线书籍封面，避免同质化

**⚠️ 通用注意事项：**
- 美需里所有人物的名字要跟**稿子里的名字一样**，否则找不到
- 新的衣服和需要调整的衣服都需要命名

## 七、QA 流程

### 正式 QA 流程
1. 集成建立QA文档，稿子导入后开始跑（**first run**）
2. 集成在文档里提问，编辑用**粉色**回答和提问
3. 编辑跑完后，由另一个集成跑 **final**
4. Final 时可能还有需要编辑确认的问题，编辑继续用粉色回答
5. 所有问题确认无误后，结束 → **GTG（Good to go）**，可以上线
6. 已修改的集成在后面写 `done`，改成**蓝色**

### QA 文档写法规范（⚠️ 最易出错）

**增行：**
```
QA文档：Before/After 10001 Add a line Katherine Speech Neutral "..."
稿子：用红色字体加行数，注意格式
```

**删行：**
```
QA文档：10001 "..."Delete
稿子：用删除线删除原句
```

**改：**
```
QA文档：原句，要改的部分加下划线，10001 "Wait! I..."
稿子：可以不改
```

### QA 注意事项
1. **不要写错ID**（ID在编辑器里唯一）
2. 增删行需写清楚行数和内容，对应部分需同步到稿子
3. 同一章节的 notes 最好按顺序写
4. **穿衣服需要写清楚从多少行到多少行**，只写行号默认只改1行
5. 新增的行数要写表情
6. 付费变免费要改 Dialogue Type
7. 注意选项协调性（删了A选项的popup，要检查B选项是否同步）

### Live QA（上线后）
- 内容上线后可根据数据修改，**不能修改脸**，其余都可以
- 一个batch的修改汇总在**一个 Google Doc 文档**里，一起给到集成
- 没有严格固定模板，格式跟正式QA差不多：写清楚每个章节、哪一行、需要怎么修改
- 不确定格式的话，可以参考 **Google Drive 里其他书籍文档中的 Live QA doc**

## 九、数据分析（⚠️ 新人最易弄混）

### 核心术语

| 术语 | 定义 |
|------|------|
| **耗钻** | 书籍在周更期间（49天）产生的全部钻石消耗（付费钻石 + 免费钻石），是评判书籍的最重要标准 |
| **付费率** | 一级PC平均付费率 |
| **ARPU** | 阅读用户人均钻耗 = 钻耗 / 阅读人数 |
| **周更期间** | 书籍上线后49天，在周更书架展示，之后下架 |

### 留存计算方式

| 指标 | 计算公式 |
|------|---------|
| **章节总留存率** | 该章完成阅读用户数 ÷ 第一章进入阅读用户数 |
| **下一章节留存率** | 该章进入阅读用户数 ÷ 上一章进入阅读用户数 |
| **章节间流失率** | 1 - (该章节完成阅读用户数 ÷ 该章节进入阅读用户数) |

### 数据工具
- **Data 4.0**（需先开通权限）：内容数据下有不同 tab
  - 【书籍数据】：查看书籍整体数据，包括**总耗钻、ARPU**等
  - 【章节转化数据】：查看**章节留存**，直达链接：https://data4-admin.crazymaplestudios.com/content/chapter/converted
- **Re-dash**：分小时报表
- **书籍总表**：查看书籍ID、上线日期、评级、简介（2018-2025周更书籍总表）

### 如何查章节留存
1. 打开 Data 4.0 → 内容数据 → **章节转化数据**：https://data4-admin.crazymaplestudios.com/content/chapter/converted
2. 右上角搜索框输入书名，点查询
3. 主要看 **章节总留存率** 这列

### 如何查总耗钻 / ARPU
- 打开 Data 4.0 → 内容数据 → **书籍数据**

### 数据分析维度
三大核心维度：**吸量、留存、付费**
- 上线后需及时拉取数据，与同期书和爆款书比较
- 如有需要可进行 Live QA 调优
- ⚠️ 如果吸量或留存有任何一项数据特别低，要特别注意

### 一、吸量分析
吸量跟**题材、封面点击率、阅读转化率**有关。

**目前平台比较吸量的题材：**
mafia、sports romance、bdsm、pregnancy、真人秀等

**封面点击率：**
- 首日一般 **25% 以上**算不错
- 数据来源：飞书周更数据表格首日数据 https://uv4iolo7hz.feishu.cn/sheets/OhOJsbMpjhn1a3tBUR6cusTynVe?sheet=a57732

**阅读量基准：**
- 首日阅读量 **6k 以上**算正常，**超过 8k** 算比较好

**钻耗基准：**
- 首日钻耗 **20w 以上**算不错
- 首周钻耗 **40w 以上**算不错
- 完结可能能上 **200w**

### 二、留存分析
**5章留存（首日）：**
- **15% 以上**算正常
- **超过 20%** 算高

**首周留存：**
- **25% 以上**算正常

### 三、付费分析
付费主要跟 **PC个数、付费率**有关。
